# HubSpot — Research Dossier

Source ruling for this Guide: HubSpot's **Integrate AI tools with the HubSpot MCP server** page is the current, purpose-built setup document and is the north star for the remote server, OAuth model, app-creation flow, and UI labels. The HubSpot user-permissions guide fills the named IAM gap. Live OAuth metadata corroborates the endpoint and discovery behavior. HubSpot's separate, locally installed **Developer MCP server** is outside this Guide.

## Server facts

- **Remote URL:** `https://mcp.hubspot.com` (HubSpot also prints it with a trailing slash in its MCP Inspector example; both identify the same shared server origin).
- **Transport:** `streamable-http`. HubSpot's MCP Inspector configuration labels this **Streamable HTTP**.
- **Authentication Option:** OAuth authorization code with PKCE (`S256`) and a manually pre-registered **MCP auth app**. The Speakeasy AI Control Plane needs the app's **Client ID** and **Client secret**. HubSpot's authorization-server metadata advertises no dynamic client-registration endpoint.
- **OAuth discovery:** the MCP server's unauthenticated challenge points to `https://mcp.hubspot.com/.well-known/oauth-protected-resource`. That document names `https://mcp.hubspot.com` as both resource and authorization server. Authorization-server metadata is available at `https://mcp.hubspot.com/.well-known/oauth-authorization-server` and advertises the authorization and token endpoints, authorization-code and refresh-token grants, `client_secret_post`, and PKCE `S256`.
- **Scopes:** do not enter scopes manually. HubSpot says an MCP auth app does not explicitly define scopes; available scopes are determined by the server's tools at installation time and by the permissions the connecting user grants. Live metadata reports an empty `scopes_supported` list.
- **Permission model:** all actions respect the connecting HubSpot user's existing permissions; a user can view or modify only records they can access in HubSpot. If server scope requirements later change, an existing user may need to reinstall the app to grant the new scopes; that is later operations, not a first-connect step.
- **Sensitive Data caveat:** when a HubSpot account has Sensitive Data enabled, the MCP server blocks activity objects such as calls, emails, meetings, notes, and tasks. This does not block connection, so it should be a short expectation-setting caveat rather than a separate setup step.
- **Availability:** HubSpot's public remote-MCP setup documentation states no subscription or seat gate. Creating and managing developer features requires a user with **Developer tools access**; a super admin can grant that permission. The intended user who authorizes the connection also needs the ordinary HubSpot permissions for the data and operations they expect to use.
- **Enable/allow gate:** the north star and targeted permissions documentation describe no separate account-level MCP enablement or allow toggle.
- **Speakeasy MCP Catalog:** present. The matched registry record is `com.pulsemcp.mirror/hubspot`, titled **HubSpot**, so this Guide renders only the catalog add-server path.

## Credential flow

An administrator creates an **MCP auth app** inside the HubSpot account. In the creation dialog, they provide an **App name**, optional **Description**, **Redirect URL**, and optional **Icon**. Enter `{{ gram.oauth.callback_url }}` directly in **Redirect URL**. HubSpot then creates the app and opens its details page, where its client credentials and redirect URLs are visible.

Values the Speakeasy AI Control Plane needs:

| Value | Origin |
| --- | --- |
| Client ID | Generated by HubSpot and shown on the app details page after {#create-mcp-auth-app} |
| Client secret | Generated by HubSpot and shown on the app details page after {#create-mcp-auth-app} |

HubSpot says the redirect URL used by the MCP client must match the configured URL. If multiple redirect URLs are configured, the first is the default. For this setup, create the app with `{{ gram.oauth.callback_url }}` as its redirect URL; do not add the MCP Inspector's localhost testing URL.

## Console walkthrough

The complete documented route is HubSpot main app > **Development** > **MCP Auth Apps** > **Create MCP auth app** > **Create** > app details page. The direct entry URL is `https://app.hubspot.com/l/mcp-auth-apps/`. No later provider-console reopen is needed before Speakeasy setup because the credentials and redirect URL are on the resulting details page.

### Open MCP Auth Apps {#open-mcp-auth-apps}

- Sign in to the HubSpot account that the connection will use.
- In the main navigation bar, select **Development**.
- In the left sidebar, select **MCP Auth Apps**. The direct documented entry URL is `https://app.hubspot.com/l/mcp-auth-apps/`.
- IAM caveat: the HubSpot permissions guide says **Developer tools access** allows a user to access and manage developer features, including app management. If **Development** is unavailable, a super admin must grant that permission or perform this setup.
- Values entered or copied: none.
- Screenshot note: capture HubSpot with **Development** in the main navigation and **MCP Auth Apps** selected in the left sidebar. Exclude unrelated account data.

### Create the MCP auth app {#create-mcp-auth-app}

- In the upper right, click **Create MCP auth app**.
- In the dialog, enter a recognizable name such as `Speakeasy AI Control Plane` in **App name**.
- Optionally fill **Description** and **Icon** according to the organization's application-record policy; HubSpot marks both as optional.
- Enter `{{ gram.oauth.callback_url }}` in **Redirect URL**. This must match the callback used by the Speakeasy AI Control Plane. Do not enter the localhost MCP Inspector callback shown in HubSpot's testing example.
- Click **Create**.
- HubSpot redirects to the app details page. Copy the displayed **Client ID** and **Client secret** into an approved password manager for {#connect-speakeasy-credentials}. The page also shows the configured redirect URLs and has **Edit info** in the upper right if the app information needs correction before connecting.
- Values entered: **App name**, `{{ gram.oauth.callback_url }}` under **Redirect URL**, and optional **Description**/**Icon**. Values copied: **Client ID** and **Client secret**.
- Screenshot note: capture the **Create MCP auth app** dialog before submission with **App name**, **Description**, **Redirect URL**, and **Icon** visible. A second capture may show the details-page layout, but all credential values must be redacted.
- Recovery: HubSpot does not document the client secret as a one-time display. If the callback was mistyped during setup, use **Edit info** on the details page and correct the redirect URL before attaching credentials in Speakeasy.

## Speakeasy setup

Canonical source: `doctrine/speakeasy-setup.md`, observed `2026-07-31T20:55:35Z`.

Per-guide values:

- Remote URL: `https://mcp.hubspot.com`
- Transport: `streamable-http` (the add form's **Transport** field is read-only)
- Authentication Option: OAuth with a manually pre-registered client; HubSpot publishes discoverable protected-resource and authorization-server metadata
- **Client ID** and **Client secret:** produced at {#create-mcp-auth-app}
- Redirect URI registered with HubSpot: `{{ gram.oauth.callback_url }}` in **Redirect URL** at {#create-mcp-auth-app}
- Provider scopes: none to enter
- Further reading: `https://developers.hubspot.com/docs/apps/developer-platform/build-apps/integrate-with-hubspot-mcp-server`

### Add the server in Speakeasy {#add-server-in-speakeasy}

In the Speakeasy AI Control Plane sidebar, under **Connect**, select **Sources**, then click **Add Source**.

Choose **3rd-party server**. On the **MCP Catalog** page, find **HubSpot** using **Search MCP servers...**, open its entry with **View**, and click **Add**. In the **Add to Project** dialog, click **Add to Project**. This creates the hosted MCP server and opens its **Overview** page.

Screenshot note: capture the **Add Source** menu on **Sources**, or HubSpot's catalog entry.

### Connect your credentials {#connect-speakeasy-credentials}

From the server's **Overview**, open **Settings**. Under **Authentication**, use **Use Discovered** when HubSpot's published metadata is offered; otherwise click **Configure Manually**. In **Attach Remote Identity Provider**, set **Client Type** to **Manual**. Paste the **Client ID** and **Client Secret (optional)** copied at {#create-mcp-auth-app}. Leave **Scope (override)** empty, then click **Attach Identity Provider**. Confirm that the sheet's **Redirect URI** matches the `{{ gram.oauth.callback_url }}` value entered in HubSpot at {#create-mcp-auth-app}.

When a user first needs HubSpot access, complete HubSpot's browser authorization flow with the intended user: select the HubSpot account, grant the presented permissions, and authorize the connection. The permissions reflect that user's existing HubSpot access.

Screenshot note: capture **Attach Remote Identity Provider** with the Redirect URI and credential fields visible and every credential value redacted.

Closing pointer: "This guide covers setup only. For anything beyond it — billing, tool behavior, limits — see HubSpot's MCP documentation at https://developers.hubspot.com/docs/apps/developer-platform/build-apps/integrate-with-hubspot-mcp-server."
